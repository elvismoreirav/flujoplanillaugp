Flujo de planillas, presupuesto y valor ganado

Análisis de procesos para cargar en UGP Integra la información de las tres obras viales: lo que lleva cada administrador de contrato en su base maestra, lo que lleva el área financiera en el seguimiento de planillas y lo que se acordó en la reunión del tablero gerencial.

  • La planilla es la unidad de carga. Cada periodo mensual produce una planilla; de ella salen los tres módulos: financiero (liquidez), presupuestario (devengado) y valor ganado (avance).
  • El estado de la planilla es dinámico. Puede volver atrás varias veces el mismo día. A UGP Integra suben solo las planillas pagadas; los demás estados se activan por proyecto y cada cambio exige un documento de respaldo.
  • UGP Integra todavía no tiene la entidad «planilla». Hoy registra rubros, entregas y valor ganado; faltan estados, reajustes, anticipo, OPIS, N° SPA, código de proceso y partidas presupuestarias.
  • Los dos Excel no hablan el mismo idioma. El «avance físico» del financiero es avance económico y el código del proyecto difiere entre archivo y sistema. Antes de automatizar hay que homologar los nombres de los indicadores.

Proceso · reunión 15:34–15:56

Ciclo de vida de una planilla

La planilla avanza obra → fiscalización → administrador de contrato → financiero → pagado. En cualquier etapa puede ser devuelta, una o varias veces, incluso el mismo día. Lo que sale hacia el área financiera ya no lo gobierna la UGP: control previo, contabilidad y tesorería son pasos internos de esa dirección.

Decisión: suben solo las planillas pagadas. Si un proyecto activa otros estados, sus planillas aparecen destacadas y no suman a los montos. Cada evento guarda quién devolvió, el motivo y el documento de respaldo.

Cómo se compone el valor de una planilla

Las columnas del seguimiento financiero encadenan cálculos que no están escritos como fórmulas. Se reconstruyeron con los valores: la planilla neta es el 80 % de la bruta (anticipo del 20 % en las tres obras), el valor a pagar es neta más reajuste, y la OPIS queda cerca de 2,9 % por debajo por retenciones y timbres.

Proceso · reunión 16:01–16:15

Un mismo dato, dos módulos

La planilla es el punto de partida de ambos módulos, pero cada uno la mide distinto. El financiero responde «¿cuánto del desembolso se consumió?»; el presupuestario responde «¿cuánto se devengó de cada partida?». Por eso la reunión pidió separar la planilla y el reajuste en columnas distintas y homologar el criterio con los tres administradores.

Para cerrar el levantamiento

Pendientes

Quedan cinco puntos. Ninguno impide empezar el módulo de planillas; el segundo sí condiciona el módulo presupuestario.

  1. Avance físico y avance económico. Recomendación: el tablero muestra los dos, con nombre y fecha de corte propios. Avance físico = EV ÷ BAC de la base maestra (lo que dice fiscalización que se ejecutó). Avance económico = planilla bruta pagada acumulada ÷ monto contractual (lo que ya se pagó). Junto a ellos, el avance programado = PV ÷ BAC. Con los archivos de Ayacucho a junio serían 7,6 % físico, 8,6 % económico y 3,4 % programado.¿Confirman estos tres nombres y definiciones?
  2. Hoja de fuentes y usos (FYU). Sus columnas (partida, fuente, codificado, certificado, comprometido, devengado, pagado, años 2024–2028) son las de una cédula presupuestaria, que normalmente se exporta del sistema financiero. Para conectarla con las planillas necesito saber tres cosas: a) Origen: ¿la exporta el área financiera desde e-GOP o desde el ERP, o se arma a mano?
    b) Frecuencia: ¿se actualiza cada mes, a cada pago o cuando la pide Dirección? Define cada cuánto se puede refrescar el saldo y el semáforo.
    c) Nivel de detalle: ¿cada fila es una partida de un proyecto (por ejemplo la partida de obras viales de Ayacucho con fuente CAF) o una partida del programa que sirve a las tres obras? Si es del programa, el sistema no puede saber cuánto devengó cada obra y habría que repartirlo.
    Y una cuarta: las columnas 2024 a 2028, ¿son lo devengado en cada año o lo planificado por año?
  3. Códigos de proyecto. La base de Ayacucho dice UGP-002, pero en el sistema UGP-002 es Calceta.¿Qué ID traen las bases maestras de Calceta y de Colón? Con eso se reasignan los tres códigos sin cruzarlos.
  4. Código e-GOP y código SERCOP. Entendí que e-GOP tiene su propio código.¿El contrato debe guardar los dos (proceso SERCOP y e-GOP) o solo el de e-GOP?
  5. Reajuste definitivo de meses anteriores. Se registra en la planilla del mes en que se factura.¿Conviene guardar, como dato opcional, a qué planilla corresponde ese reajuste? Sirve para conciliar con la certificación, sin cambiar dónde suma.
